# 페이지 관리 패널과 선택 동작 — local.4

현재 버전은 4.1.3-beta.2-local.4 / versionCode 418이다. 기존 미커밋 펜·올가미·OCR·필기 캐시 복구를 유지하며 로컬 소스와 APK만 변경한다.

## 변경

- 두 열의 420dp 패널을 한 열의 188dp 패널로 변경했다. 매우 좁은 창에서는 156dp까지 줄인다. 미리보기 크기는 패널 너비에 따라 작아지고, 화면에 보이는 항목만 만드는 재활용 구조와 드래그 순서 이동을 유지한다.
- 항목 위·아래 여백을 각각 2dp로 줄였다. 미리보기 사이 간격은 66dp에서 52dp로 줄이고, 점 세 개 메뉴의 48dp 터치 영역은 유지한다.
- 가로 화면에서 접근성 드래그의 시작 미리보기가 재활용되어도 이동을 끝낼 수 있도록, 종료 요청을 화면에 붙어 있는 목록에서 처리한다.
- 드래그 미리보기 순서를 바꿀 때 현재 보이는 목록 위치를 유지한다. 재활용 목록의 스크롤 기준점이 이동한 페이지를 따라가며 손가락 아래 삽입 위치를 바꾸던 문제를 수정했다.
- 페이지 패널과 필기 영역을 나란히 배치한다. 상단 기본 도구 모음은 패널을 열어도 원래 위치와 너비를 유지한다. 펜을 선택했을 때 나오는 팔레트 바는 남은 필기 영역의 너비에 맞춰 중앙에 배치하며, 항목이 넘치면 한 줄로 스크롤한다. 실행 취소·페이지/배율 표시도 필기 영역 안에 배치된다.
- 상단 페이지 관리 버튼과 문서 옵션 버튼의 순서를 바꿨다. 문서 옵션이 맨 오른쪽이다.
- 미리보기의 점 세 개 메뉴는 버튼 가까이에 뜨는 플로팅 메뉴다. 메뉴를 여는 것만으로 현재 페이지를 바꾸지 않는다.
- PR 준비 전 후속 수정에서 메뉴의 `이 페이지로 이동`을 제거하고 `앞 페이지 추가`·`뒷 페이지 추가`를 넣었다. 메뉴를 연 페이지의 바로 앞·뒤에 같은 용지 종류와 크기의 빈 페이지를 만들고 새 페이지를 선택한다. 저장 완료 뒤 대상 페이지 ID로 위치를 다시 확인하며, 패널이 열려 있으면 새 페이지를 중앙 정렬한다.
- 삭제 뒤 저장된 순번에 빈칸이 있어도 추가·복제 위치가 화면의 순서와 일치하도록, 삽입 전에 기존 페이지 순번을 정리한다. 보이는 순서가 그대로인 순번 정리에서는 기존 OCR 결과를 무효화하지 않는다.
- 삭제는 메뉴를 누른 페이지 ID로 처리하며 추가 확인창을 띄우지 않는다. 다른 페이지를 삭제해도 현재 페이지는 유지한다. 현재 페이지를 삭제하면 다음 페이지, 마지막 위치라면 이전 페이지를 선택한다. 마지막 한 페이지 보호와 저장 완료 대기는 유지한다.
- 미리보기나 페이지 번호로 이동하면 현재 확대 배율을 유지하면서 선택한 페이지의 중심을 남은 필기 영역의 중심에 맞춘다.

## 검증

2026-10-27, API 35 에뮬레이터의 별도 `com.inkforge.note4.debug` 패키지에서 확인했다. 기존 사용자 앱과 노트는 초기화하지 않았다.

| 검사 | 결과 |
| --- | --- |
| `python tools/test_native.py` | 후속 수정 포함 JVM 184개, 실패·오류 0개 및 Debug 빌드 통과 |
| `python tools/run_native_validation.py tools --output build/validation-tools` | 도구 회귀 5개 묶음 통과 |
| 최종 Debug·계측 APK 빌드 | 통과 |
| `python tools/build_apk.py --variant both --ocr-beta` | 최종 Update·SideBySide APK 빌드 통과 |
| 최종 APK 버전·패키지·서명·ZIP·16KiB 정렬·고정 PDFium 자산 검사 | 두 APK 모두 통과 |
| 1202dp 가로 화면 전체 페이지 관리 검사 | 통과 |
| 811dp 세로 화면 전체 페이지 관리 검사 | 통과 |

실제 터치 입력으로 상단 도구 모음과 각 버튼의 위치가 그대로 유지되는지, 펜 팔레트가 남은 필기 영역 안에서 중앙에 배치되는지 확인했다. 페이지 이동은 중심 좌표와 확대 배율을 함께 검사했다. 메뉴를 연 페이지와 현재 페이지를 다르게 둔 삭제, 추가 확인창 없음, 저장 대기, 마지막 한 페이지 보호, 삭제 후 선택 위치와 재열기도 통과했다.

드래그는 양방향 이동, 연속 접근성 이동, 13페이지 가장자리 자동 스크롤과 복귀, 취소·패널 닫기·바깥에 놓기, 저장 대기, 이동 중 페이지 목록 변경, 실행 취소·다시 실행 보존을 포함한다. 가로 화면의 드래그 스크롤 기준점과 접근성 이동 종료 문제를 수정한 뒤 두 화면 크기 모두 전체 검사를 다시 통과했다.

초기 페이지 패널 검사 기록은 `build/page-panel-anchor-ui-1202.log`, `build/page-panel-anchor-ui-811.log`에 있다. 앞·뒤 페이지 추가 후 전체 관리 검사를 다시 실행한 최종 기록은 `build/page-menu-and-text-ui-811.log`, `build/page-menu-final-ui-1202.log`다. 현재 페이지가 아닌 메뉴 대상 앞·뒤 추가, 빈 페이지의 용지·크기, 저장 대기, 삭제 후 순번 빈칸과 재열기, OCR 내보내기·가져오기 보존을 포함한다. JVM·도구 검사 기록은 `build/text-final-native-tests.log`, `build/text-final-tools-validation.log`다. 초기 패널 화면 캡처는 `build/page-panel-complete-{1202,811}-{pen-palette,sidebar,popover}.png`다.

최종 설치 파일은 `build/apk/bad-note-Android-4.1.3-beta.2-local.4-Update.apk`와 `build/apk/bad-note-Android-4.1.3-beta.2-local.4-SideBySide.apk`다. 앞·뒤 페이지 추가와 [텍스트 후속 수정](TEXT-LOCAL.4-KO.md)을 포함한 최종 빌드 기록은 `build/text-final-release-build.log`, APK 검사 결과는 `build/text-final-update-verification.json`과 `build/text-final-sidebyside-verification.json`에 있다. 기존 로컬판과 같은 로컬 인증서를 사용하며, 공개 Beta 2와는 서명이 달라 공개판 위에 덮어쓸 수 없다. [설치 범위](RELEASE-4.1.3-BETA.2-KO.md)를 따른다.

이전 고밀도 필기의 무끊김 미달 상태는 [local.3 검증](INK-LOCAL.3-KO.md)을 그대로 따른다. 이번 검사는 페이지 관리 UI 회귀이며 실제 Galaxy/S Pen 성능 검증을 대신하지 않는다.
