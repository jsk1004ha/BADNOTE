# BADNOTE 4.1.3 Beta 1

[PR #10](https://github.com/jsk1004ha/BADNOTE/pull/10)의 OCR 검색·결과 표시 수정에 필기·스크롤·확대 중 백그라운드 OCR 자원 경합 완화를 추가한 베타입니다.

- 필기·스크롤·핀치 확대 중에는 자동 OCR의 새 작업과 다음 처리 단계를 중단합니다. 입력이 끝난 뒤 기존 6.5초 대기 시간이 지나면 자동 인식을 다시 요청합니다.
- 긴 연속 노트에서 매 프레임 모든 페이지를 훑는 대신 화면 주변 페이지 범위를 이진 탐색합니다. 기존 표시 범위와 좌표 계산은 유지하며 잘못된 페이지 크기에는 기존 탐색을 사용합니다.
- OCR 작업 스레드를 Android 백그라운드 우선순위로 실행합니다. 수동 OCR 요청은 유지합니다.
- 실행 중인 ML Kit 작업은 실제 완료될 때까지 입력 비트맵과 실행 허가를 보존합니다. 원본 획, 압력·시간 샘플, 실행 취소·다시 실행, 교정, 검색과 Room 스키마는 유지합니다.
- PR #10의 검색 색인·인식 결과 표시 및 변경되지 않은 이미지 OCR 재사용을 포함합니다.

## 설치

- `bad-note-Android-4.1.3-beta.1-Update.apk`: 기존 `com.inkforge.note4` 업데이트용.
- `bad-note-Android-4.1.3-beta.1-SideBySide.apk`: `com.inkforge.note5` 병행 설치용. 이전 병행 설치 앱이 있으면 업데이트합니다.
- 버전 `4.1.3-beta.1`, versionCode 413, 최소 Android 6.0. 이전 베타와 같은 인증서로 서명합니다.
- GitHub Source code ZIP/TAR.GZ와 배포 APK 두 개를 제공합니다. 정식 Latest 릴리스는 변경하지 않습니다.

## 검증 범위

동일한 API 35 에뮬레이터에서 PR #10 기준 빌드와 수정 빌드에 같은 입력을 재생합니다. 필기 접촉 중 자동 작업 허용량, 300획·3,600점 레이아웃을 사용하는 24회 요청의 작업량, 작업 스레드 우선순위와 원본 샘플 보존을 확인합니다. 10,000개 페이지 메타데이터의 같은 스크롤·확대 60회에서 소프트웨어 Canvas 그리기 CPU 시간·탐색량·화면 픽셀을 비교하고, 다양한 크기·배율·경계에서 기존 표시 판정과 일치하는지 확인합니다. 단위 테스트, Android lint, 실제 Task의 시간 초과·완료·비트맵 수명, 저장·교정·검색 검사와 APK 서명·패키지·버전·네이티브 라이브러리 검사를 거칩니다.

이 검사는 자동 OCR의 자원 사용 억제를 확인합니다. 실제 Galaxy/S Pen의 화면 지연·FPS 개선율과 ML Kit 내부 스레드 자원 사용은 미측정입니다. 이미 시작한 SDK 작업은 안전하게 완료시키므로 펜을 대는 순간 모든 OCR CPU 사용이 즉시 사라지는 것은 아닙니다. 인식 모델이나 인식률을 낮추는 변경은 없습니다.

배포 빌드는 `-PbadnoteOcrBeta=true`로 새 레이아웃·혼합 소스 경로를 활성화합니다. 수식 전용 엔진, PDF 문자별 위치 매핑, 실필기 인식률 비교는 후속 작업입니다.
