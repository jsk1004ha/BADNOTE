# OCR 4.1.2 첫 구현 단계

기준: 2026-10-14, `v4.1.1-beta.1`, commit `9bfdf4be8f501b52cf4a10a006f354a1404813d4`.
기준 tree SHA는 `be79277e9f8d97445b8e892a9d889e8ab9ff357b`다. commit SHA와 구분한다. 이 기록은 전체 14단계 계획을 완료했다는 뜻이 아니다.

## 구현

계획 PR01~05의 합성 회귀·최소 계약·페이지 지문·원자 스냅샷·보호 묶음과 작은 획 배정을 시작했다. 계약 모듈은 제조사 타입이나 app 의존성이 없다. 후보 원문·엔진·언어·요청·가설·native rank를 보존하며 점수는 null이다.

레이아웃 v2는 폭/높이가 0인 획도 이웃 그래프에 포함한다. 공간 버킷(48개), 획별 후보(24개), 줄별 후보(32개)를 제한하고, 연결한 두 획만이 아니라 병합된 묶음 전체의 폭과 높이를 확인한다. 상한 초과는 검토 사유로 기록한다. 작은 획은 실제 이웃 묶음의 거리로 배정하며 모호하거나 먼 점은 unresolved로 남긴다. 문자나 기호를 만들어 넣지 않는다. 원래 `captureSeq`, 세션, fragmentOrder, 배열 순서와 시간 없는 입력 처리는 유지한다.

PR07의 수식 미지원 상태와 PR10의 실제 완료 기반 입력 수명을 먼저 적용했다. 유료/선택 수식 SDK는 추가하지 않았다. debug에서만 혼합 소스를 처리하고 자료 렌더링에서 이미 디지털 인식한 필기·기존 텍스트 객체를 제외한다. PDF는 현재 이미지 경로로 처리하며 정밀 위치 추출을 완료한 것으로 표시하지 않는다.

PR11의 보수적인 교정 연결을 추가했다. sourceIdentity가 있는 교정은 원본 목록·내용·내용 유형이 같은 일대일 영역에만 적용한다. v1 교정은 기존 inputDigest 비교를 유지한다. 복제 시 현재 결과에 연결된 교정만 새 지문으로 매핑하며 detached 교정을 새 결과에 붙이지 않는다. 결과 JSON은 v1 읽기와 호환되는 추가 필드이며 Room 마이그레이션은 없다.

## 재현 입력과 측정

`OcrLayoutRegressionTest`의 최초 세 입력은 제공된 `LayoutProbe.kt`의 좌표를 옮긴 **synthetic** fixture다. 기존 레이아웃을 실제로 실행하는 version=1 비교에서 `각`은 2영역, 낮은 소수점은 unresolved, 정상 소수점은 1영역이다. version=2는 구성 획을 동일 영역에 전달한다. 추가 시험은 합성 두 줄, 먼 점, 0차원 획, 다른 세션의 늦은 받침, 원본 불변·지문 변경을 포함한다.

실제 `1+1=2` 실패 획과 작성자 분리 시험 세트가 제공되지 않아 실필기 기준 실행은 **미측정**이다. B0를 현 버전의 baseline으로 바꾸지 않았고 CER/정확도/지연을 가짜 수치로 작성하지 않는다. E0/E2의 실모델 비교와 physical S Pen 검증은 후속 관문이다.

## 검사

로컬 Python OCR 평가/도구 테스트와 별도 JVM에서 생산 소스의 기하·지문·교정·lease·소스 계획 JUnit을 실행한다. JVM 보조 실행은 Android 전체 앱 빌드나 실제 ML Kit 추론의 대체 증거가 아니다. 로컬 Gradle은 JVM 네트워크 연결이 막혀 의존성 해석 단계에서 실패했으며 APK 검증은 GitHub CI가 수행한다.

CI 명령과 에뮬레이터 완료 marker는 `.github/workflows/ocr-beta.yml`, `tools/check_ocr_beta_device.sh`에 있다. APK 게시 job은 모든 검사의 성공에 종속된다. 결과가 없는 현재 문서만으로 CI 통과나 프리릴리스 게시를 주장하지 않는다. 최종 실행 링크는 PR과 GitHub Releases에서 확인한다.

## 후속 관문

작은 획의 동일 원본 대체 가설·예산 재시도, 확정 문맥, 전용 수식 엔진 실호출, PDF 문자/Unicode 위치, 영역별 이미지 좌표, 검토 UI, 실필기 품질·기기 성능 측정과 정식 활성화는 아직 완료하지 않았다. 이 베타에서 실패 원본을 확보하여 다음 PR의 같은 입력 비교에 사용한다.

참고: [ML Kit Digital Ink Android 공식 안내](https://developers.google.com/ml-kit/vision/digital-ink-recognition/android). 한 줄 WritingArea, 동일 좌표 단위, 모델 내 후보 순위와 실제 획순을 유지한다.
